    06 / Security

    How This Site Is Secured

    We applied what we learned in this course to the e-Portfolio itself. Each control below points to where it is implemented in the source code.

    • Content Security Policy

      Only scripts and styles hosted on this site can run. Inline scripts, inline styles, plugins, forms and <base> tags are blocked, and only YouTube's privacy-enhanced player may be embedded. This limits the damage if an XSS bug ever slipped in.

      <meta http-equiv="Content-Security-Policy"> in index.html

    • Output encoding

      Every value from the content file is HTML-encoded (& < > " ') before it reaches the page, so text can never be interpreted as HTML or script.

      esc() in js/main.js

    • Input allow-listing

      Repository links are only accepted if they start with https://, which rejects javascript: and data: URLs. For videos, only an 11-character YouTube ID is extracted with a strict pattern; the rest of the link is discarded.

      safeUrl() and youtubeId() in js/main.js

    • Safe external links

      Links that open in a new tab use rel="noopener noreferrer", so the opened page cannot take control of this tab (reverse tabnabbing).

      repoButton() in js/main.js

    • Privacy-respecting embeds

      Videos load from youtube-nocookie.com only when scrolled into view, with a strict referrer policy that sends only our site's origin.

      video() in js/main.js

    • HTTPS everywhere

      GitHub Pages enforces HTTPS for this site, and the policy's upgrade-insecure-requests rule upgrades any stray http:// request.

      GitHub Pages settings + CSP

    • Zero third-party code

      No frameworks, CDNs, fonts, analytics or trackers. Everything is written by us, which removes the risk of a compromised dependency (OWASP A03:2025 Software Supply Chain Failures).

      css/ and js/ folders

    • Minimal data

      The site has no forms, sets no cookies and collects nothing. The only thing stored is your light/dark mode choice, kept in your own browser.

      localStorage "theme" in js/main.js

    Known limitations

    GitHub Pages does not let us set custom HTTP response headers, so the policy is delivered through a <meta> tag. That means clickjacking protection (frame-ancestors / X-Frame-Options), X-Content-Type-Options and CSP violation reporting cannot be enabled here. Hosting on a platform that supports a headers file (such as Netlify or Cloudflare Pages) would close this gap.
